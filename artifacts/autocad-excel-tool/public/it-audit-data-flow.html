1. Executive Summary

This document provides a technical assessment of the CAD Data Engine tool for IT security audit and approval purposes. The tool is a browser-based web application used by engineering teams to extract, review, and export structured data from AutoCAD Drawing Exchange Format (DXF) files and apply CSV-based edits back to those files.

Key Security Finding: The CAD Data Engine processes all files entirely within the user's local web browser. No engineering data, drawings, or exported files are transmitted to any external server, cloud service, or third party at any point. The tool is architecturally equivalent to running a local desktop application.

Files are accessed via the browser's standard File System Access API — they are read into browser memory (RAM) and processed entirely on the local device. Output is written back to the local filesystem. No data traverses the network.

4. Data Residency & Transmission Confirmation

Confirmed: Zero Data Transmitted to External Systems.
Engineering drawings (DXF files), extracted tag data, CSV exports, and all intermediate processing results remain exclusively within the user's browser session on their local device. When the browser tab is closed, all in-memory data is discarded. No copies are retained by the application, its hosting provider, or any third party.

ComponentTechnologyWhere It RunsRole

DXF Write-Back Custom TypeScript module Browser (client-side) Patches DXF attribute values; writes file to local disk via File System Access API

Web Worker Isolation: Heavy processing (DXF parsing, entity classification) runs in a browser Web Worker — a sandboxed background thread that has no access to the network, cookies, or local storage. This further ensures that engineering data cannot leave the device even through indirect channels.

7. Deployment Options for Company Portal

Option A — Hosted via URL Link (Recommended — Simplest)

The tool is accessible at a published URL. Employees access it through their browser. No installation required. Suitable for teams with internet access.

  • IT action required: Whitelist the application URL in corporate proxy/firewall
  • Data risk: None — no engineering data leaves the user's device

Option B — Intranet / Self-Hosted (Recommended for Strict Data Policies)

The application can be exported as a static build (HTML/CSS/JS bundle) and hosted on an internal web server (IIS, Nginx, Apache) within the company network. No internet connection is required once deployed.

  • IT action required: Copy static files to internal web server; configure MIME types for .js/.css
  • Data risk: None — processing remains local; internal server only delivers code
  • Benefit: Fully air-gapped operation; no outbound internet required

Option C — SharePoint / Intranet Portal Embed

The hosted URL can be embedded as an <iframe> in SharePoint or any company intranet portal page.

IT Recommendation: For the strictest data governance, use Option B (self-hosted). The static build is a portable folder of files with no dependencies on external services. Once deployed internally, the tool operates with zero outbound network traffic of any kind.
